# Таверна — календарь сессий D&D

## База знаний Obsidian

Откройте папку `knowledge` как хранилище в Obsidian. Начальная заметка: [00 Главная](knowledge/00%20Главная.md). Здесь собраны состояние проекта, архитектура, инструкции, решения и журнал. Правила дальнейшего ведения закреплены в `../AGENTS.md`; база обновляется при работе над проектом.

Общий календарь группы с регистрацией по логину и паролю, без email.

## Начало работы

1. Пока опубликованный сайт закрыт для владельца, зарегистрируйте первый аккаунт. Он автоматически станет администратором. Не открывайте публичный доступ до этого шага.
2. Создайте кампанию. Создатель становится мастером этой кампании; глобальная роль администратора и роль мастера независимы.
3. Пригласите игроков ссылкой на кампанию. После регистрации или входа по этой ссылке участник автоматически присоединяется к нужной кампании и сразу получает доступ к календарю и столу. Имя и выбранный часовой пояс сохраняются в профиле участника; повторный вход не меняет существующую роль и профиль. Несуществующее приглашение отклоняется.
4. Каждый, включая мастера, указывает свои свободные промежутки в выбранном часовом поясе.
5. Выберите длительность сессии. Календарь объединит соседние свободные промежутки, найдёт пересечение для всех участников, исключит назначенные сессии и предложит ближайшее время. Мастер подтверждает подходящий вариант.

## Время

Пояса в интерфейсе подписаны относительно Москвы: `+0 МСК · Москва`, `+2 МСК · Екатеринбург`, `-2 МСК · Берлин`. Для регионов с летним временем смещение рассчитывается на дату события; в списке поясов показана текущая разница. В базе по-прежнему сохраняются IANA timezone и UTC-моменты.

В базе хранятся UTC timestamps в миллисекундах. Пояс определяется браузером и может быть изменён в календаре. IANA timezone используется для ввода и отображения. Например, 10:00 в Москве и 12:00 в Екатеринбурге соответствуют одному моменту. При осеннем повторении времени выбирается первый момент; несуществующее местное время при весеннем переводе часов отклоняется. Для удобного назначения начало округляется вперёд к 15 минутам. Автоматическое обновление данных — каждые 20 секунд, когда вкладка видима.

## Администрирование

Администратор видит пользователей и кампании, блокирует/разблокирует аккаунты, выдаёт и снимает административные права, удаляет кампании с подтверждением. Изменить собственные права или заблокировать себя через панель нельзя. В каждой комнате можно совмещать роли «ДМ» и «Игрок». В разделе «Моя группа» ДМ открывает «Изменить роли» на карточке участника и выбирает одну или обе роли. Роли действуют только в этой комнате; глобальные права администратора независимы. Любой ДМ назначает/отменяет игры, управляет ролями и участниками, а также получает инструменты мастера на игровом столе. Нельзя снять или удалить последнего ДМа, а у участника должна оставаться хотя бы одна роль. Создатель не может покинуть собственную кампанию, но может передать роль ДМа другому участнику. Совмещение ролей не дублирует участника в подборе общего времени; доступность всех ДМов учитывается наравне с игроками. Игроки управляют только собственными свободными часами; могут покинуть группу. Все права проверяются на сервере.

Пароли сохраняются только как salted PBKDF2 hashes (Web Crypto, SHA-256, 100000 итераций). Сессии имеют случайные 256-битные токены; в базе хранится только SHA-256 токена. Cookie — HttpOnly, SameSite=Lax, Secure на HTTPS, срок 30 дней. Смена пароля завершает активные сессии. Есть ограничение частоты попыток входа и смены пароля. Автоматического восстановления по почте нет.

## Локальная работа

Локальный игровой стол: после входа и выбора кампании откройте «Игровой стол» в навигации. Запуск `npm run dev` поднимает приложение и отдельную комнату WebSocket только на loopback. Инструкция и границы прототипа: [docs/table-prototype.md](docs/table-prototype.md). Мастер может создавать несколько сцен, готовить их за ширмой, переключать группу между картами, дублировать и архивировать сцены с восстановлением. Все участники могут двигать любые токены активной сцены. Мышь и WASD передают движение до 20 раз в секунду с плавным отображением у остальных игроков; конечная позиция сохраняется после завершения жеста. Есть личная библиотека аккаунта, общая библиотека кампании, загрузка файлов перетаскиванием и токенизатор с круглым кадрированием и обводками. Состояние комнат и загруженные материалы сохраняются в `.sites-runtime/table-rooms`, отдельно от исходников и опубликованного сайта.

Основная тема — тёмная, со светлым текстом, золотыми акцентами и иллюстрацией таверны. Кнопка солнца/луны в верхней панели переключает на светлую тему и обратно; выбор запоминается в браузере. Подробности исследования, источники и описание иллюстрации: `docs/design-research.md`.

- `npm run dev -- --port 5173 --hostname 127.0.0.1`
- `node node_modules/typescript/bin/tsc --noEmit`
- `npm test` — планировщик и регрессии: повторяющийся час, ночные сессии, обозначения относительно МСК.
- `node scripts/integration.test.mjs` — только свежая локальная база и сервер на 127.0.0.1:5173. Скрипт создаёт временные QA-аккаунты и удаляет только свои тестовые записи.

Новая база требует сборки и применения SQL из `drizzle/` через локальные команды Wrangler из README стартера. Хостинг Sites применяет миграции при публикации. Локальная база и база опубликованного сайта независимы. Без сессии отображается экран входа/регистрации.

Пункт «Тест» открывает виртуальный стол с библиотеками, токенизатором, сценами и движением мышью/WASD. На сайте используются отдельные таблицы D1 `test_table_*` и R2 `test-vtt/`; подробности и проверка транспорта описаны в `docs/table-prototype.md`.

## Чекпоинты

`node scripts/checkpoint.mjs descriptive-label` сохраняет архив исходников вне checkout: `F:\DND CALENDAR\checkpoints`. Ведётся журнал README.md. Зависимости, Git, build output, credentials и runtime-базы не архивируются. Чекпоинт исходников не является резервной копией живой базы данных; для восстановления данных нужна отдельная копия D1.

Проверка ролей локально: `node scripts/roles-integration.test.mjs` — совмещение, выдача и снятие прав, изоляция комнат, защита последнего ДМа, календарь и серверный транспорт тестового стола. Скрипт создаёт и удаляет только собственные временные QA-записи.

# Таверна — календарь сессий D&D

Общий календарь группы с регистрацией по логину и паролю, без email.

## Начало работы

1. Пока опубликованный сайт закрыт для владельца, зарегистрируйте первый аккаунт. Он автоматически станет администратором. Не открывайте публичный доступ до этого шага.
2. Создайте кампанию. Создатель становится мастером этой кампании; глобальная роль администратора и роль мастера независимы.
3. Пригласите игроков ссылкой на кампанию. Участник регистрируется, открывает ссылку и нажимает «Присоединиться».
4. Каждый, включая мастера, указывает свои свободные промежутки в выбранном часовом поясе.
5. Выберите длительность сессии. Календарь объединит соседние свободные промежутки, найдёт пересечение для всех участников, исключит назначенные сессии и предложит ближайшее время. Мастер подтверждает подходящий вариант.

## Время

В базе хранятся UTC timestamps в миллисекундах. Пояс определяется браузером и может быть изменён в календаре. IANA timezone используется для ввода и отображения. Например, 10:00 в Москве и 12:00 в Екатеринбурге соответствуют одному моменту. При осеннем повторении времени выбирается первый момент; несуществующее местное время при весеннем переводе часов отклоняется. Для удобного назначения начало округляется вперёд к 15 минутам. Автоматическое обновление данных — каждые 20 секунд, когда вкладка видима.

## Администрирование

Администратор видит пользователей и кампании, блокирует/разблокирует аккаунты, выдаёт и снимает административные права, удаляет кампании с подтверждением. Изменить собственные права или заблокировать себя через панель нельзя. Мастер назначает/отменяет игры и убирает участников из своей группы. Игроки управляют только собственными свободными часами; могут покинуть группу. Все права проверяются на сервере.

Пароли сохраняются только как salted PBKDF2 hashes (Web Crypto, SHA-256, 100000 итераций). Сессии имеют случайные 256-битные токены; в базе хранится только SHA-256 токена. Cookie — HttpOnly, SameSite=Lax, Secure на HTTPS, срок 30 дней. Смена пароля завершает активные сессии. Есть ограничение частоты попыток входа и смены пароля. Автоматического восстановления по почте нет.

## Локальная работа

- `npm run dev -- --port 5173 --hostname 127.0.0.1`
- `node node_modules/typescript/bin/tsc --noEmit`
- `node --test scripts/scheduler.test.mjs`
- `node scripts/integration.test.mjs` — только свежая локальная база и сервер на 127.0.0.1:5173. Скрипт создаёт временные QA-аккаунты и удаляет только свои тестовые записи.

Новая база требует сборки и применения SQL из `drizzle/` через локальные команды Wrangler из README стартера. Хостинг Sites применяет миграции при публикации. Локальная база и база опубликованного сайта независимы. Демо-кампания отображается только для знакомства; её записи не сохраняются в базе.

## Чекпоинты

`node scripts/checkpoint.mjs descriptive-label` сохраняет архив исходников вне checkout: `F:\DND CALENDAR\checkpoints`. Ведётся журнал README.md. Зависимости, Git, build output, credentials и runtime-базы не архивируются. Чекпоинт исходников не является резервной копией живой базы данных; для восстановления данных нужна отдельная копия D1.

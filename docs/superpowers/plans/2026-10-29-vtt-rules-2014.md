# VTT: кубики, обзор и бой (D&D 2014)

Статус: реализация по прямому запросу пользователя, локально. Исходная архитектура сохраняется.

## Аудит

- React19/TypeScript/Vinext, Konva; `scene.ts` валидирует токены и команды, `room.ts` хранит сцены и строит представления.
- `/table`: `scripts/table-server.mjs`, очередь комнаты, файловые снимки, ephemeral движение.
- `/test`: `hosted-room.ts`, D1 JSON и CAS, WebSocket либо HTTP polling. Библиотеки — локальное хранилище/R2.
- Сейчас все участники активной сцены получают все её токены. Общего фильтра видимости и боевых данных нет. Метаданные квитанций и motion требуют отдельного контроля.
- Существующие изменения общей линейки и музыкального окна сохраняются. Архив до работы: `checkpoints/2026-10-29T12-21-28-924Z-before-vtt-dice-fog-initiative.tar.gz`.

## 1. Кубики

`lib/table/dice.ts`: строгий парсер суммы групп NdS и целых модификаторов, d4/6/8/10/12/20/100, max40 физических кубов, rejection sampling crypto.getRandomValues; преимущество/помеха для d20. Видимость public / private (автор+ГМы) / gm (только ГМы). Результат и актёр создаются сервером; NPC подпись только ГМ. История в room payload, идемпотентные команды. Приватные события/квитанции не передаются посторонним. Снимки hosted сравниваются по авторизованной проекции, а не только версии БД.

`app/table/dice-tray.tsx`, `dice-stage.tsx`, `lib/table/dice-geometry.ts`: Three.js + cannon-es, собственные геометрия/текстуры, физические столкновения и WebAudio. Записанная физическая траектория воспроизводится с маркировкой граней, согласованной с серверным исходом. d100 — пара d10 (десятки/единицы, 00+0=100). Числовой доступный результат сохраняется при отсутствии WebGL/отключённой анимации. История видимых бросков переживает reconnect; старые броски не анимируются заново.

Проверки: парсер, суммы/adv/dis, percentile, подмена результатов, права/квитанции, публичная синхронизация и reconnect.

## 2. Туман

`lib/table/fog.ts`: сегменты стен/дверей, пересечения и ray-casting, ограничение радиуса, owned-token vision. Видно сейчас — геометрический LOS; исследовано — серверные ячейки памяти по userId; неисследованное — непрозрачно. Явные GM reveal/hide области. Настройки по умолчанию выключены, старые сцены совместимы.

`scene.ts`, `room.ts`: данные, команды ГМа, просмотр глазами выбранного игрока как серверная проекция; скрытые токены/боевые поля/объекты удаляются из представления до сериализации. Рисунки и изображения токенов тоже проверяются. Движение при активном тумане доставляется отфильтрованными снимками; ephemeral события не раскрывают скрытые позиции. Общие измерения имеют ту же проверку видимости. Неизвестные ID в командах игрока дают одинаковую ошибку доступа.

`fog-controls.tsx`, `table-canvas.tsx`: рисование стен/дверей/областей двумя точками, управление дверями, радиус зрения, preview игрока и слои fog. Сохранение внутри существующего scene JSON, без миграции основного хранилища.

Проверки: стены/открытые двери/дальность, память, права владения, сериализация и motion/API без скрытых токенов, сохранение и reconnect.

## 3. Инициатива

`lib/table/combat.ts`, `combat-panel.tsx`: участники связаны с tokenId; HP/maxHP/AC/initiativeMod/visibility/owner и состояния хранятся на токене. Список боя содержит уникальный ID, raw roll, total, tie-order и эффекты. NPC stats видит ГМ; игрок видит чужие только с разрешением. Автоброски через тот же серверный RNG. Round/currentId переживают пересортировку, удаление текущего корректно выбирает следующего, wrap повышает раунд. Тайбрейк 2014 — явный устойчивый порядок ГМа (по умолчанию порядок добавления), опционально серверный d20 с устойчивым fallback. Игрок меняет собственные HP/статусы; ГМ управляет боем и NPC. Изменения через существующие команды и снимки.

Проверки: стабильная сортировка, tie-order/reroll, права, секретные NPC, добавление/удаление, раунды, общие HP и восстановление.

## Завершение этапов

После каждого этапа: targeted tests + TypeScript, список файлов и инструкции проверки в журнале. По завершении — полный regression suite/build, проверка двух транспортов и отсутствие task-owned процессов. Существующий пользовательский preview5178 сохраняется. Никакой публикации до отдельного запроса.

## Особые риски

- Не использовать общий broadcast приватных roll records/commandId.
- Любой motion-commit и доступ к placed assets должны использовать ту же проекцию.
- D1 CAS retry не должен повторно бросать кубики.
- UI preview не даёт клиенту возможность запрашивать чужие права.
- Не выдавать npc stats через generic update/duplicate либо старые снимки.

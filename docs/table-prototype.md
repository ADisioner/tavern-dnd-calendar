# Игровой стол: вкладка «Тест»

Игровой стол открывается из выбранной кампании через пункт «Тест» (`/test?campaign=…`). Для входа нужен аккаунт участника кампании; создатель кампании получает роль мастера. Без входа главная страница показывает форму входа/регистрации. Приглашение в кампанию сохраняется после входа.

## Размещение на сайте

На хостинге комнаты, квитанции команд, временные движения и присутствие хранятся в отдельных таблицах `test_table_*` D1; файлы — в R2 с префиксом `test-vtt/`. Календарные записи не изменяются действиями на столе. Схема добавляется миграциями `0001` и `0002`. Локальный файловый транспорт остаётся доступен через `npm run dev`.

Клиент сначала подключается к WebSocket Worker. Worker проверяет обновления общей комнаты и временных движений через D1 с интервалом 100 мс; клиент сглаживает позиции между обновлениями. Если WebSocket недоступен, включается HTTP-транспорт с теми же проверками прав, блокировками токенов и сохранением конечного положения. Фактическая задержка зависит от сети и времени запросов D1; это экспериментальный транспорт для небольшой группы. Кадры не переписывают сцену: итоговое положение фиксируется один раз при завершении жеста.

Проверка размещённого транспорта локально: после применения всех миграций запустите `node scripts/run-framework.mjs dev --port 5173 --hostname 127.0.0.1`, затем `node scripts/table-integration.test.mjs --hosted`. Проверяются два аккаунта, WebSocket, HTTP-резерв, приватные сцены, конфликты движений, R2 и личная/общая библиотека. Скрипт удаляет только созданные им QA-записи и файлы.

## Запуск локально

Запускайте из корня проекта. Требуется уже установленный `node_modules`.

```sh
npm run dev -- --port 5173 --hostname 127.0.0.1
```

Откройте `http://127.0.0.1:5173`. Для обычной работы одного аккаунта используйте этот адрес во всех его вкладках. Для проверки двух независимых аккаунтов в одном браузере можно открыть мастера на `127.0.0.1`, а игрока на `localhost`: эти адреса используют отдельные cookies, но одну локальную базу и комнату.

При первом запуске на новой локальной базе создайте сборку и примените начальную миграцию. Эти действия нужны только для пустой базы; уже применённые миграции повторно не запускайте.

```sh
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_grey_wolf_cub.sql
```

После этого запускайте dev-сервер указанной выше командой. Локальная D1-база хранится в `.wrangler/state` и независима от любой размещённой базы.

## Что можно проверить

- Постоянный стол на кампанию с несколькими сценами: стартовая карта таверны или изображение, выбранное мастером из библиотеки. Пропорции загруженной карты сохраняются внутри поля 1600 × 1120 px.
- Панорамирование СКМ в любом инструменте, пробелом с перетаскиванием или инструментом руки, масштабирование колёсиком/жестом, подгонка карты и привязка фигур к клеткам. Удерживайте Ctrl или Alt, чтобы временно двигать фигуру без привязки. Выберите фигуру и используйте WASD (те же физические клавиши Ц/Ф/Ы/В в русской раскладке): один шаг на клетку, удержание плавно повторяет шаги без ожидания сети. В текстовых полях и открытых диалогах эти клавиши не перемещают токен.
- Участники видят одну сцену и список подключённых игроков. Любой участник может добавлять и перемещать любые фигуры, включая фигуры мастера. Любой участник редактирует свойства фигур и назначает владельцев; владение не ограничивает движение. В карточке выбранного токена доступно «Удалить с карты», Delete удаляет выбранные фигуры; файл в библиотеке остаётся. Конфликт одновременного движения одной фигуры проверяется по версии объекта.
- Мастер может менять фон карты, размер и видимость сетки и запустить проверку сцены на 100 токенах. Кнопка «Вернуть карту таверны» восстанавливает начальный фон.
- Сцены и активный выбор группы сохраняются локально в `.sites-runtime/table-rooms/<campaign>.room.json`. Это данные выполнения, а не исходники: не включайте эту папку в архивы исходного кода и не удаляйте её для очистки QA, если хотите сохранить созданные сцены.

Локальный dev-скрипт создаёт WebSocket-сервис только на loopback-интерфейсе и выбирает для него случайный свободный порт. При каждом запуске создаётся новый секрет сервиса. Сервер приложения выдаёт короткоживущий подписанный билет, а сервис периодически, перед командами и перед отправкой состояния заново проверяет сессию и права участника на стороне приложения. API `/api/table` намеренно отвечает HTTP 503 вне локального режима; онлайн-транспорт этого прототипа пока не настроен.

## Плавная синхронизация движения

Перетаскивание мышью и удержание WASD используют отдельный WebSocket-поток. Клиент передаёт промежуточные позиции с частотой до 20 Гц; остальные участники плавно интерполируют их за 85 мс. Кадры применяются напрямую к узлам Canvas через requestAnimationFrame, без полной перерисовки React-дерева на каждый кадр. WASD анимирует шаги локально и не ждёт записи предыдущего шага.

- Начало жеста кратко захватывает конкретный токен. Одновременно можно двигать разные фигуры; второму участнику не разрешается перетянуть уже захваченную. На чужом движущемся токене показываются голубая рамка и имя участника. Захват освобождается после подтверждения, отмены или обрыва связи; срок продлеваемого захвата — 3 секунды. При отправке конечной позиции захват сохраняется до подтверждения записи; клиент ждёт до 10 секунд, затем переподключается.
- Промежуточные кадры не записываются в JSON/D1, не меняют ревизии и не рассылают весь снимок сцены. Проверяется последовательность кадров, версия токена, границы поля и принадлежность видимой сцены. В фоне повторно проверяются сессия и членство; для промежуточного потока срок кэша разрешений ограничен 2,5 секунды. Начало жеста использует этот же ограниченный кэш. Финальная запись проверяет действующую сессию заново.
- После отпускания мыши/клавиши сохраняется конечная позиция одной атомарной записью; участникам отправляется компактное подтверждение изменённого токена. История всего пути не хранится. Статус «В сети» отображает соединение и не мигает между шагами; время внизу обновляется по подтверждённой записи.
- При потере фокуса или скрытии вкладки текущий жест завершается. При обрыве соединения неподтверждённый предпросмотр отменяется, восстанавливается последняя сохранённая позиция. При ошибке записи положение откатывается, ошибка отображается пользователю. Кадры не накапливаются при переполнении сетевой очереди.
- Полные снимки остаются для входа, восстановления соединения и изменений структуры сцен. Приватные заготовки мастера не попадают в поток игрокам.

Проверка на шести WebSocket-клиентах: 20 Гц без записи файла и без обращения к авторизации на каждый кадр; конечный пакет около 400 байт. В реальном локальном аккаунте и браузере одно удержание WASD дало 34 промежуточных кадра и одно сохранение. Проверено перетаскивание мышью, конфликт захвата, отмена при отключении, отказ записи и приватность подготовительных сцен. Эти измерения относятся к loopback на текущем компьютере, а не к размещённому сайту или интернет-соединению. FPS на отдельном мобильном устройстве пока не измерялся.

## Несколько сцен и подготовка за ширмой

В панели мастера появился раздел «Сцены кампании». До 50 сцен, включая архив. Игроки получают только общую активную сцену; заготовки и архив мастера не включаются в их снимки комнаты.

- «Новая сцена» создаёт пустую сцену и открывает её только мастеру. Группа остаётся на прежней карте. Из библиотеки можно выбрать карту и расставить токены, пока игроки продолжают пользоваться активной сценой.
- Нажатие на название сцены открывает личный предпросмотр мастера. Над картой видна полоса «За ширмой» с названием сцены, на которой остаётся группа.
- «Показать группе» переключает игроков на подготовленную сцену. Все токены, карта и настройки сетки каждой сцены сохраняются независимо.
- Карандаш переименовывает сцену. Кнопка копирования создаёт независимую копию с новыми ID фигур, сохраняя карту, владельцев, позиции и сетку.
- Неактивную сцену можно архивировать. Вкладка «Архив» позволяет восстановить её; безвозвратного удаления сцен нет. Активную сцену сначала нужно сменить.
- Запоздавшие команды игрока для прежней сцены после переключения отклоняются. Все участники по-прежнему могут добавлять и двигать любые токены общей сцены. Сценами и подготовкой управляет только мастер кампании.
- Личные изображения из неактивных сцен недоступны игрокам через файловый API, пока не используются в активной сцене. Материалы, явно положенные в общую библиотеку, доступны группе независимо от выбора сцены.

Формат комнаты — версия 2. При первом открытии прежний `<campaign>.json` читается и переносится в новый `<campaign>.room.json`; исходный файл остаётся нетронутым как копия до перехода. Повторные открытия используют новый файл. Повреждённые сохранения не заменяются пустыми сценами. При переподключении мастер возвращается к активной сцене группы, а подготовленные сцены остаются в списке; обновление билета в уже открытой вкладке сохраняет предпросмотр.

## Личная и общая библиотеки

Откройте значок папки слева или «Открыть библиотеку» в инспекторе сцены. «Моя библиотека» принадлежит аккаунту и доступна из разных кампаний; «Общая библиотека» принадлежит текущей кампании. Любой участник загружает материалы кнопкой или перетаскиванием. Есть поиск и фильтры: изображения, токены, карты, PDF-документы и аудио.

- Поддерживаются PNG, JPEG, WebP, GIF, PDF, MP3, OGG и WAV; каждый файл — до 8 МБ. Тип проверяется по сигнатуре на сервере. Лимит аккаунта — 500 файлов / 256 МБ, включая скрытые из библиотеки материалы.
- Изображение можно добавить кнопкой «На стол». Все участники видят размещённое изображение, даже если оригинал был личным; остальные личные материалы владельца не раскрываются. Только мастер меняет фон кнопкой «На карту».
- Владелец может перевести материал в общую или обратно в личную библиотеку. Материалы других пользователей остаются личными даже для мастера. Мастер может убрать файл из общей библиотеки своей кампании.
- «Убрать из библиотеки» скрывает запись. Байты сохраняются, чтобы не сломать уже созданные сцены. Сокрытие файла или перевод обратно в личную библиотеку не скрывает изображение, уже размещённое на столе.
- Изменения общих библиотек обновляются через WebSocket. Файлы скачиваются через авторизованный маршрут приложения; сессия и членство проверяются заново. Прямое чтение файлов из runtime-каталога через сайт не предоставляется.

Данные библиотеки: `.sites-runtime/table-rooms/library/index.json` и файлы `<uuid>.bin`. Как и сцены, они исключены из исходных checkpoints. Это локальное хранилище; для резервирования загруженных материалов нужна отдельная копия runtime-папки при остановленном dev-сервисе.

## Встроенный токенизатор

У изображения в библиотеке нажмите «Токенизатор». Перетаскивайте изображение в круге или используйте ползунки позиции/масштаба. Выберите цвет, толщину и вид обводки: сплошная, двойная или пунктирная. Толщина 0 убирает обводку. «Сохранить токен» создаёт отдельный PNG 512 × 512 с прозрачными углами в выбранной библиотеке; исходное изображение остаётся. Готовый токен добавляется на стол кнопкой «На стол».

## Проверки

Быстрые тесты логики запускаются из корня:

```sh
npm test
```

Для интеграционной проверки нужен работающий локальный сервер на `127.0.0.1:5173` и подготовленная локальная D1-база. В отдельном терминале выполните:

```sh
node scripts/table-integration.test.mjs
```

Скрипт создаёт временные QA-аккаунты, кампанию и подключения мастера/игрока, проверяет совместную сцену, движение любых токенов игроками и ограничения инструментов мастера, затем удаляет созданные им записи и файл сцены. Если процесс прервётся, не запускайте проверку повторно, пока не разберётесь с оставшимися тестовыми данными. При намеренном сохранении QA-фикстуры команда очистки такая:

```sh
node scripts/table-integration.test.mjs --cleanup
```

Эта команда предназначена только для фикстуры, ранее сохранённой интеграционным скриптом в игнорируемой папке `outputs`. Не публикуйте и не пересылайте содержимое QA-фикстуры.

## Границы прототипа и дальнейшая работа

Проверено 28 октября 2026: 46 unit/regression-тест, TypeScript и production-сборка; интеграция стола через реальные локальные аккаунты. Отдельно проверены HTTP-прокси библиотеки, загрузка от игрока, доступы к личным и общим материалам, запрет доступа посторонним и запросов изменения с чужого origin. Для библиотек в браузере ранее проверены загрузка файла, кадрирование перетаскиванием, цвет/толщина/тип обводки, сохранение PNG и размещение на столе. В браузере проверены создание сцены и отдельный предпросмотр мастера. Серверные тесты покрывают переименование, копирование, переключение, архив и восстановление. Для WASD проверены шаги W/D, удержание D, остановка после отпускания и отсутствие движения при вводе текста. Серверные тесты проверяют сохранность старого файла, независимость сцен, сокрытие заготовок/личных файлов от игрока и восстановление после перезапуска. PNG проверяется как 512 × 512 с прозрачными углами. Измерение FPS ещё не проводилось.

Обновление 2026-10-29: серверные кубики/3D, туман войны и инициатива реализованы в локальной ветке; [файлы, права, ограничения и проверки](vtt-2014-implementation.md). Размещённая версия обновляется только отдельной публикацией. Транспорт на хостинге предназначен для тестирования небольшой группой.

Публикация выполняется только по явному запросу пользователя; загрузка в GitHub требует отдельного запроса. Перед существенными изменениями и публикацией сохраняйте датированный checkpoint в `F:\DND CALENDAR\checkpoints`, исключая runtime-данные и credentials.

## Общие рисунки и группы

Кисть и ластик доступны всем участникам. Выберите цвет/толщину, проведите штрих на карте; ластик стирает штрих целиком. Рисунки общие и сохраняются в сцене. Рамка на пустом месте и Shift+клик выделяют несколько фигур. «Склеить» создаёт постоянную группу, «Разъединить» освобождает её участников. Перетаскивание любого токена группы, WASD и стрелки панели двигают её целиком. СКМ/пробел временно включают камеру даже в режиме кисти. Удаление выделения атомарно, движущиеся фигуры защищены от редактирования и удаления.

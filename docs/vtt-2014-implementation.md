# Три модуля VTT — D&D 2014

Дата: 2026-10-29. Реализовано и проверено локально; Site v16 опубликован на https://notgamba.ru, исходный код синхронизирован с GitHub main. Фактические идентификаторы и границы production-проверки приведены в разделе «Публикация».

## Аудит и архитектура

Сохранены React19/TypeScript/Vinext, Konva, файл комнаты для локального WebSocket и JSON комнаты в D1 с CAS для hosted режима. [План](superpowers/plans/2026-10-29-vtt-rules-2014.md) составлен до реализации. Новые поля имеют значения по умолчанию, поэтому текущий код читает прежние сохранения. Отдельные таблицы для этих трёх модулей не добавлялись: расширены JSON комнаты и сцены.

В локальном preview оба маршрута `/table` и `/test` используют локальный WebSocket, если настроен `TABLE_LOCAL_SECRET`. На размещённом сайте без локального секрета выбирается hosted WebSocket/HTTP fallback. QA отдельно проверяет hosted HTTP/D1; флаг `storage=hosted` в API библиотеки нужен именно для такой локальной проверки и не переключает пользовательские комнаты автоматически на другое хранилище.

Результаты, права и состояния вычисляет сервер. Клиент отправляет команды. Проекции для конкретного получателя строятся до сериализации; кэш авторизации не используется при доставке новых снимков и hosted poll. Промежуточные motion-данные и выдача файлов тоже проходят проверку видимости. Секретные поля NPC удаляются из обычных и повторных подтверждений движения.

## Этап 1 — 3D Dice

### Файлы

- [room.ts](../lib/table/room.ts), [table-server.mjs](../scripts/table-server.mjs), [hosted-room.ts](../lib/table/hosted-room.ts), [hosted-connection.ts](../app/table/hosted-connection.ts), [use-table-room.ts](../app/table/use-table-room.ts): сохранение, авторство, адресная доставка, reconnect и серверный курсор авторизованного представления.
- [table-app.tsx](../app/table/table-app.tsx), [table.css](../app/table/table.css), [package.json](../package.json), lockfile: кнопка, адаптивное окно и зависимости.
- [dice.test.mjs](../scripts/dice.test.mjs), [table-server.test.mjs](../scripts/table-server.test.mjs): математика, физические геометрии, приватность, подмена результатов, восстановление.

### Поведение и проверка

Откройте кнопку кубиков в нижнем правом доке. Введите `2d6+3`, затем `d20+5` с преимуществом/помехой. Поддерживаются суммы групп и отрицательные модификаторы, d4/d6/d8/d10/d12/d20/d100; максимум 40 физических кубиков на бросок. d100 визуализируется парой d10: десятки/единицы, 00+0=100.

Результат формируется серверным `crypto.getRandomValues` с rejection sampling. Клиентские `total`, автор или результаты не принимаются командной схемой. Физическая траектория рассчитывается до проигрывания; номера граней согласованы с авторитетным исходом. Косметическая случайность анимации не участвует в результате. Нет ассетов или исходников Owlbear Rodeo.

«Всем» видно всем участникам, «Автор и ГМ» — автору и мастерам, «Только ГМ» — только мастерам; автор такого blind-броска получает подтверждение без результата. Подпись NPC может задать только ГМ. Отдельные лимиты истории не позволяют приватными бросками вытеснить публичные записи у посторонних. Клиент получает до 200 разрешённых записей, личный private bucket хранит до 50; публичный и GM buckets — до 200 каждый, общий предел хранилища 5000. При первом подключении/переподключении старые броски не анимируются. История отображает время в выбранном часовом поясе.

Исходные проверки этапа: 11/11 dice+WS, TypeScript и build. Финальные проверки дополнены тестом изоляции лимитов истории и снятия роли ГМа на открытом соединении. В браузере проверены бросок `2d6+3`, группа всех типов и фактический WebGL-рендер; исправлена ошибка отрицательного индекса первого кадра. При отсутствии WebGL остаётся числовой результат. Звуки включаются отдельно; браузер может требовать пользовательский жест. Аудиовыход на физическом устройстве не измерялся.

### Файлы

- [table-server.mjs](../scripts/table-server.mjs), [hosted-room.ts](../lib/table/hosted-room.ts), [hosted-socket.ts](../lib/table/hosted-socket.ts), [use-table-room.ts](../app/table/use-table-room.ts), [hosted-connection.ts](../app/table/hosted-connection.ts), [API table](../app/api/test/table/route.ts): защищённые снимки, motion, измерения и preview.
- [hosted-library.ts](../lib/table/hosted-library.ts), [API library](../app/api/table/library/route.ts), [hosted-table-checks.mjs](../scripts/hosted-table-checks.mjs): запрет private images скрытых токенов и отдельная проверка D1/R2 в локальной среде.
- [fog.test.mjs](../scripts/fog.test.mjs), [table-server.test.mjs](../scripts/table-server.test.mjs), [table-input.test.mjs](../scripts/table-input.test.mjs): стены, двери, память, пиксели, права и отмена инструмента.

### Поведение и проверка

ГМ: «Туман войны» → включить автоматическое зрение → назначить владельца токену в существующей форме → указать радиус в ft → выбрать «Стена»/«Дверь» и протянуть отрезок. Открыть/закрыть/удалить дверь можно в списке. Ручные области — прямоугольники, применяются в порядке создания. «Сбросить память» очищает память и ручные области, сохраняя стены.

Выберите игрока в предпросмотре: снимок фильтруется сервером с его правами. Выйдите в «Полный обзор ГМа» для редактирования. Текущий обзор прозрачен, исследованный затемнён, неисследованный непрозрачен. Память хранится ячейками 20px; текущий LOS токенов рассчитывается по геометрии и дальности. Камера/масштаб применяются одинаково к карте и маскам. При включённом тумане игрок управляет принадлежащими ему фигурами; без тумана прежнее совместное управление обычными токенами сохраняется.

При движении токена изменение зрения подтверждается конечной серверной позицией. Ephemeral координаты чужих токенов при активном тумане не используются для раскрытия скрытой области. Невидимые токены и рисунки отфильтрованы, чужая память и стены не попадают в клиентский JSON. У скрытого private token image HTTP-доступ запрещён. PNG/JPEG/GIF фона маскируются перед отправкой байтов. Для WebP и карт свыше 4MP предусмотрено создание PNG-копии под размер сцены; неподдерживаемый исходник игроку не выдаётся. Оригинал остаётся в библиотеке ГМа. Туман надо включать до показа секретной карты: уже полученные пользователем данные отозвать невозможно.

Исходные проверки этапа: 9/9 fog+WS, 31/31 fog+scene, TypeScript/build. Сквозная проверка D1 подтвердила исчезновение NPC за закрытой дверью, появление при открытии и сохранение секретных HP. В браузере подтверждён предпросмотр с чёрной областью за закрытой дверью. Проверка кадров/пикселей и частных изображений автоматизирована.

## Этап 3 — Initiative Tracker

### Файлы

- [combat.ts](../lib/table/combat.ts): схема участника/эффекта, серверные броски инициативы, групповой бросок, порядок при ничьей, раунды, сроки эффектов, права, редактирование HP и безопасное удаление текущего участника.
- [scene.ts](../lib/table/scene.ts): HP/временные HP/maxHP/AC/initiativeMod, shareStats/hidden, эффекты и combat state. Участник нормализован: собственный UUID + tokenId; имя, принадлежность, HP/КД/модификатор/состояния берутся из единственной записи токена. roll/total/tie-order находятся в записи участника.
- [fog.ts](../lib/table/fog.ts), [room.ts](../lib/table/room.ts), [hosted-room.ts](../lib/table/hosted-room.ts): проекции NPC, согласованность удаления/копии сцены, повтор CAS с сохранением серверной энтропии.
- [combat-panel.tsx](../app/table/combat-panel.tsx), [table-app.tsx](../app/table/table-app.tsx), [table-canvas.tsx](../app/table/table-canvas.tsx), [table.css](../app/table/table.css): трекер, выбор связанного токена, характеристики, эффекты и HP-полоска/маркер хода на карте.
- [combat.test.mjs](../scripts/combat.test.mjs), [vtt-2014-integration.mjs](../scripts/vtt-2014-integration.mjs): сортировка, группы, tie reroll, round wrap, эффекты, права и восстановление.

### Поведение и проверка

ГМ выбирает токен → «Инициатива и бой» → добавляет его → задаёт HP/КД/модификатор → «Бросить всем» → «Начать бой». Кнопка следующего хода меняет активную фигуру; по окончании списка увеличивается раунд и уменьшается срок эффектов. Удаление текущего участника выбирает следующего, удаление последнего корректно завершает бой. Удаление токена убирает его ссылку из боя. Дублирование сцены начинает отдельный encounter с пустым списком боя и новой памятью исследования.

Временные HP задаются в характеристиках токена и регулируются кнопками в инициативе. Они хранятся на токене отдельно от записи участника, поэтому удаление из инициативы и повторное добавление сохраняют их; удаление самого токена удаляет и эти данные. В карточке участника обычные кнопки HP −1/+1 заменены на числовое поле суммы и действия «Урон»/«Лечение»: урон сначала расходует временные HP, остаток снимается с обычных HP; лечение восстанавливает обычные HP и ограничено maxHP. Проекции скрывают временные HP вместе с остальными характеристиками, если для зрителя действует hideStats. Панель ГМа подписывает hideStats как «Скрыть характеристики» и не меняет видимость токена. Отдельное действие контекстного меню «Скрыть для игроков»/«Показать игрокам» меняет `token.hidden` серверной командой `vision`; оно доступно только ГМу, и скрытая фигура остаётся видна мастеру.

Для группы одинаковых NPC задайте одинаковое поле группы инициативы: один серверный d20 используется для группы. Ничья по умолчанию решается устойчивым порядком, который ГМ меняет стрелками, учитывая решение игроков. Дополнительно доступен серверный d20 при ничьей с устойчивым fallback. Это соответствует выбору порядка в [правилах D&D 2014](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/combat#Initiative).

Игрок может один раз бросить инициативу своего участника, менять его HP/характеристики и эффекты. ГМ может перебрасывать и управлять всем боем. HP ограничены 0..maxHP. Эффект может быть постоянным или иметь срок в раундах; связанный статус отражается значком на токене. Изменения HP и состояний хранятся на том же токене, поэтому трекер и карта не расходятся.

Скрытый участник отсутствует в проекции игрока вместе с tokenId. У чужого участника HP/КД/модификатор/эффекты и raw/total инициативы не передаются без `shareStats`; ГМ разрешает показ отдельной галочкой. Порядок разрешённых строк сохраняет серверный порядок даже при скрытых числовых итогах. Проверять следует двумя аккаунтами, включая повторный вход/переподключение.

Первичные проверки этапа: 12/12 общих dice/fog/combat, TypeScript. Дополнительно проверены групповой общий бросок и дополнительный d20. Реальные local WS и hosted D1 проверки подтвердили раунд 2 после полного круга, HP/эффекты на токенах и HP после reconnect. В браузере подтверждены начало боя, подсветка текущего токена, следующий ход и HP −1. Адаптивность проверена при 390×844; физическое мобильное устройство не использовалось.

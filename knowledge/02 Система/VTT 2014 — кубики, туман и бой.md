# VTT 2014 — кубики, туман и бой

## Назначение

Три интегрированных модуля существующего стола без замены транспортов и хранилищ. План, файлы, пошаговая проверка и фактические результаты: [отчёт](../../docs/vtt-2014-implementation.md).

## Факты и правила

- Кубики: server crypto RNG, формулы/группы, d4..d100, преимущество/помеха d20; d100 как два процентильных d10, 00+0=100. Public / автор+ГМ / только ГМ. Результат и автор не берутся из клиента. До 200 разрешённых записей в проекции; private buckets не вытесняют чужую публичную историю. 3D — Three/cannon-es, процедурные модели и звуки, fallback на числовую историю.
- Туман выключен в старых сценах по умолчанию. Стены/двери, owned-token radius/LOS, память по пользователю (20px), ручные прямоугольники. Проекция убирает невидимые токены/рисунки, стены и чужую память; защищены motion и запросы private images. PNG/JPEG/GIF карта маскируется сервером; WebP/>4MP надо подготовить в PNG инструментом ГМа. Ранее полученные игроком сведения отозвать невозможно.
- Инициатива: запись участника UUID+tokenId с raw d20/total и tie order. HP/временные HP/maxHP/AC/модификатор/эффекты хранятся на токене. Временные HP редактируются в трекере и сохраняются при удалении и повторном добавлении участника в очередь; hideStats скрывает их вместе с остальными характеристиками. Серверные автоброски, общий бросок группы, round wrap, истечение эффектов, безопасное удаление текущего. Ничья 2014 — решение ГМа/игроков, либо дополнительный d20. NPC-числа/эффекты скрыты, пока ГМ не разрешит shareStats. Игрок управляет собственными HP/эффектами и первым броском инициативы; ходами управляет ГМ.
- Переключатель «Скрыть характеристики» в панели боя влияет только на hideStats и не скрывает токен. В контекстном меню ГМ отдельно выбирает «Скрыть для игроков»/«Показать игрокам»; сервер скрывает фигуру только в проекции игрока.
- Состояние сохранено в прежних JSON полях комнаты/сцены, отдельной миграции для трёх модулей нет. В локальной среде выбор `/table` vs `/test` сам по себе не выбирает D1: bootstrap использует локальный WS при настроенном local secret. D1 отдельно проверяется QA через hosted API и `storage=hosted` для библиотеки.
- Три модуля опубликованы в Site v16; уточнения приватности и поведения интерфейса 2026-10-30 опубликованы в Site v17. Старый код со strict схемами не обязан читать новые поля JSON; rollback требует согласованного checkpoint данных.

## Уточнения 2026-10-30 — опубликовано в v17

- [Кубики](../../app/table/dice-tray.tsx) рисуются отдельным прозрачным 3D-слоем поверх стола при закрытом лотке. Новые разрешённые сервером результаты проигрываются очередью, история при входе не переигрывается. Публичные события получают все участники, приватная серверная фильтрация сохранена. Физическая анимация локальная; её траектория на разных клиентах может отличаться, итог совпадает с сервером.
- [Обзор ГМа](../../lib/table/fog.ts) объединяет зрение принадлежащих игрокам нескрытых токенов и память исследования. Маска ГМа по умолчанию затемняет на 10%; [ползунок](../../app/table/fog-controls.tsx) сохраняется только в localStorage. Предпросмотр конкретного игрока остаётся непрозрачным вне разрешённого обзора. Маска сначала рисуется на отдельном canvas, затем накладывается с общей opacity, чтобы destination-out корректно вырезал видимые области.
- [Бой](../../lib/table/combat.ts): hideStats скрывает HP/макс.HP/КД/модификатор/эффекты/бросок инициативы даже от владельца; галочку меняет только ГМ. shareStats действует при выключенном hideStats. Обычные публичные статусы на фигуре остаются видимыми. Игрок не редактирует скрытые характеристики.
- Токен с явно заданными 0 HP исключается из инициативы сервером, остаётся на карте. Удаление текущего корректно передаёт ход, при переходе через конец очереди увеличивает раунд; пустая очередь завершает бой. После лечения ГМ добавляет фигуру заново. Отсутствующее HP не считается нулём.
- [Панель боя](../../app/table/combat-panel.tsx) при закрытии остаётся смонтированной; свёрнутый док показывает раунд/текущий ход, выбор открыто/закрыто сохраняется для кампании в браузере. Данные боя остаются на сервере.

## Временные HP и видимость — 2026-10-30

В `combat.ts` добавлены временные HP и числовая команда изменения HP с серверной валидацией и правами владельца/ГМа. Карточка участника принимает целое число и кнопкой выбирает урон либо лечение: урон сначала уменьшает временные HP, затем обычные; лечение увеличивает обычные HP до максимума. Временные HP хранятся на токене и переживают удаление и повторное добавление участника инициативы. Настройка «Скрыть характеристики» управляет только hideStats: игрок видит токен без числовых характеристик, а ГМ видит их. Отдельное действие контекстного меню ГМа «Скрыть для игроков»/«Показать игрокам» задаёт token.hidden серверной командой `vision`; скрытый токен остаётся видим ГМу. ## Пошаговые атаки — 2026-10-30, локальная реализация

Команда `combat-attack` проверяется на сервере: бой должен идти, атакующий должен быть текущим участником инициативы, игрок должен владеть атакующим, а скрытая цель недоступна. Владение питомцем использует то же поле `ownerId`; его запись инициативы даёт отдельный ход. Интерфейс позволяет выбрать цель, кость и количество костей, знак и числовой модификатор; сервер использует существующий ограниченный `evaluateDice`. Итог атаки сравнивается с КД. При попадании урон сначала расходует временные HP, затем обычные; результат сохраняется как последний исход боя. Отдых и заклинания автоматических правил не имеют: можно вручную задать характеристики или применить числовое лечение вне боя. Поле фракции отсутствует, поэтому выбирается любой другой видимый токен, не принадлежащий самому игроку.

Проверка текущего изменения: [combat.test.mjs](../../scripts/combat.test.mjs), полный набор 195/195, `npx tsc --noEmit`, production build. Lint в репозитории не проходит из-за 17 ошибок. Опубликовано в Site v19 и GitHub `main`. См. [[План улучшений игрового стола]] и [[2026-10-30]].

# Аккаунты и права

Вход по логину и паролю без email. По документации первый зарегистрированный аккаунт получает административную роль; регистрацию владельца следует выполнить до открытия новой пустой установки группе.

## Два уровня прав

Глобальный администратор управляет пользователями и кампаниями. Роль ДМ действует внутри конкретной кампании и не выводится автоматически из глобального администрирования.

В `members.role` сохраняются `master`, `player` или совмещение через запятую. Использовать `hasCampaignRole`; для протокола стола `tableRole` выбирает `master`, если роль присутствует. Старые одиночные значения остаются допустимыми.

- Участнику нужна хотя бы одна роль.
- Нельзя удалить или снять последнего ДМа.
- Любой ДМ управляет назначением игр, ролями и сценами своей кампании.
- Игрок меняет собственную доступность; на активной сцене участники могут двигать любые токены.
- Создатель не покидает собственную кампанию; роль ДМа можно передать.
- Повторный вход по приглашению не сбрасывает существующую роль и профиль.
- Все разрешения проверяются сервером.

## Авторизация

По README пароли хешируются salted PBKDF2 SHA-256, в БД хранится хеш сессионного токена. Cookie HttpOnly, SameSite=Lax, Secure на HTTPS; смена пароля завершает сессии. Есть ограничения частоты запросов. В базу знаний не копировать значения cookies, пароли, хеши реальных пользователей или QA-фикстуры.

## Изменение ролей администратором — 2026-10-30

Реализовано локально: в админ-панели внутри каждой кампании перечислены участники; «Изменить роли» назначает ДМ, игрок или обе роли. [Admin API](../../app/api/admin/route.ts) повторно проверяет активные административные права в атомарном SQL UPDATE и запрещает снимать последнего ДМа. [Проверки](../../scripts/admin-roles.test.mjs) исполняют реальный SQL на in-memory SQLite, включая отзыв прав между аутентификацией и обновлением. На сайте пока прежняя версия.

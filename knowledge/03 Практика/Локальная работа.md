# Локальная работа

Все команды выполнять из `F:\DND CALENDAR\tavern-calendar-sites`. Требование стартера: Node.js >=22.13.0. Набор команд сверять с [package.json](../../package.json).

## Запуск

```powershell
npm run dev -- --port 5173 --hostname 127.0.0.1
```

Запускается приложение и локальный WebSocket стола. Runtime-состояние не включать в исходные архивы.

## Выбор проверок

```powershell
npm test
node node_modules/typescript/bin/tsc --noEmit
npm run lint
npm run build
```

Запускать проверки, соответствующие изменению. Удачная сборка не означает публикацию и не заменяет сценарии с разными аккаунтами. Для изменений только Markdown достаточно проверки заметок, ссылок и настроек Obsidian.

## Интеграционные сценарии

Нужен подготовленный локальный сервер `127.0.0.1:5173` и локальная D1. Общий интеграционный скрипт по README рассчитан на свежую локальную базу.

```powershell
node scripts/integration.test.mjs
node scripts/invite-integration.test.mjs
node scripts/roles-integration.test.mjs
node scripts/table-integration.test.mjs
```

Сначала прочитать выбранный скрипт и его условия: он создаёт временные аккаунты/кампании. После прерванного запуска проверить оставшиеся фикстуры перед повтором. Не выполнять на живой базе группы. Не записывать содержимое фикстур в знания.

Миграции описаны в [README стартера](../../README.md): применяются по порядку к локальной базе через Wrangler с `--local`; не переигрывать уже применённые SQL. Публикация и загрузка GitHub требуют отдельных запросов по [[Правила проекта]].

Каждый фактический запуск фиксировать в журнале с датой, командой и результатом. Старые числа тестов не переносить как результат текущего запуска.

## Завершение локальных проверок

По требованию пользователя после тестов закрывать запущенные для задачи серверы, наблюдатели, сеансы автоматизации и временные среды вместе с дочерними процессами. Оставлять сервер работающим только по явному запросу пользователя.

При запуске фиксировать ID процессов/сеансов и порты. Сначала завершать штатно; принудительно останавливать только подтверждённые остатки собственных тестов. После завершения, ошибки или прерывания проверки убедиться, что процессы вышли и их порты освобождены. Не завершать все `node.exe` по имени: среди них работают Codex, плагины, другие чаты и приложения. Ненужные собственные REPL/среды автоматизации сбрасывать штатными инструментами.

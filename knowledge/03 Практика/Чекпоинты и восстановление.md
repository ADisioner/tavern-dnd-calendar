# Чекпоинты и восстановление

Архивы: `F:\DND CALENDAR\checkpoints`, журнал: [checkpoints/README.md](../../../checkpoints/README.md). Предыдущие копии сохраняются.

Перед существенными изменениями из корня checkout:

```powershell
node scripts/checkpoint.mjs descriptive-label
```

[Скрипт checkpoint](../../scripts/checkpoint.mjs) создаёт датированный `.tar.gz` и добавляет запись в журнал. Исключает зависимости, Git, runtime-папки, сборки, `.env*`, `.dev.vars*` и TypeScript build state. После появления Obsidian также исключает персональное состояние workspace, cache и корзину хранилища. Обязательная проверка перед архивом: не появились ли секреты или runtime-данные под другими именами.

Markdown базы знаний и переносимые `.obsidian/*.json` входят в источник. Корневой `F:\DND CALENDAR\AGENTS.md` находится вне checkout: перед его изменением нужна отдельная датированная копия и запись в журнале.

## Восстановление

1. Выбрать архив и прочитать его назначение в журнале.
2. Просмотреть содержимое: `tar -tzf <archive>`.
3. Распаковать сначала в новую отдельную папку, сравнить с текущими файлами.
4. Сохранить текущую версию до переноса выбранных файлов обратно.
5. После восстановления исходников выполнить подходящие проверки из [[Локальная работа]].

Исходный checkpoint не содержит живые данные D1, локальные комнаты и загруженные игровые материалы. Для их восстановления нужна отдельная резервная копия данных; автоматический экспорт данных этой задачей не настроен.
